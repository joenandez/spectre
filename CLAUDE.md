# CLAUDE.md

This file provides guidance to Claude Code when working with this repository.

## Project Overview

spectre is a Claude Code and Codex plugin providing a structured agentic workflow: Scope → Plan → Execute → Clean → Rebase, with standalone prune/test/sweep prompts available when only one closeout phase is needed. It's a meta-prompt orchestration system where prompts invoke subagents.

## Architecture

### Meta-Prompt Orchestration

Skills are contract-form workflow prompts that:
1. Parse user arguments
2. Spawn parallel subagents (`@spectre:dev`, `@spectre:analyst`, etc.)
3. Subagents execute specialized prompts
4. Main prompt synthesizes findings and produces artifacts

### Subagents

| Agent | Purpose |
|-------|---------|
| `@spectre:dev` | Implementation with MVP focus |
| `@spectre:analyst` | Understand how code works |
| `@spectre:finder` | Find where code lives |
| `@spectre:patterns` | Find reusable patterns |
| `@spectre:web-research` | Web research |
| `@spectre:tester` | Test automation |
| `@spectre:reviewer` | Independent review |

### Knowledge Skills

SPECTRE stores maintained knowledge and work accounts as typed, revisioned records in the user-level project store. SessionStart provides a bounded discovery index, while agents use task-aware search and verified exact loads before relying on a record. The primary captures qualifying accepted Execute findings and maintains the same work account through Ship/Create PR; `/spectre:learn` is an on-demand capture or work-summary route, not knowledge-skill authoring or a mandatory post-work step.

## Working in This Repo

### Source of Truth

- `plugins/spectre/` is the canonical source for skills, agents, hooks, and plugin assets.
- `plugins/spectre-codex/` is generated by `npm run sync-codex -- --quiet`. Do not hand-edit it.
- If generated Codex output is wrong, fix the canonical source or the translator in `scripts/`, then regenerate.
- Always review generated diffs, but maintain the source tree, not the generated tree.

### Standard Change Workflow

1. Run `git status --short --branch`.
2. Edit the canonical source:
   - skills: `plugins/spectre/skills/<skill>/SKILL.md`
   - agents: `plugins/spectre/agents/*.md`
   - learning/runtime helpers: `plugins/spectre/hooks/scripts/*`
   - installer/update behavior: `src/`
   - translators/sync behavior: `scripts/`
3. Run `npm run sync-codex -- --quiet`.
4. Run `npm run sync-codex -- --check --quiet`.
5. Run focused tests for the touched area; use `npm test` for translator, installer, or shared runtime changes.

### Adding Workflow Skills

1. Create or update a skill in `plugins/spectre/skills/`
2. Follow existing patterns:
   - contract form: Purpose, Inputs, Working Set, Outputs + DONE, Method/guardrails, Handoff, Escalate-If
   - late-bound runtime data rather than baked-in branch/diff/file lists
   - "Next Steps" output for workflow continuity
3. Prefer prompts that call focused skills over duplicating another skill's body.
4. For rewrites/compression, use `spectre-rewrite-skill` as the QC lens.
5. Run `npm run sync-codex -- --quiet` to regenerate `plugins/spectre-codex/`.
6. Run `npm run sync-codex -- --check --quiet`.

### Adding Agents

1. Create markdown in `plugins/spectre/agents/`
2. Include:
   - Role and mission sections
   - Methodology for how the agent works
   - Tool preferences

### Modifying Learning Helpers

Update Node.js scripts in `plugins/spectre/hooks/scripts/`. They are helper scripts invoked by Spectre commands, not Codex/Claude startup hooks.

### Generated Codex Bundle

`scripts/translators/skills.cjs` rewrites Claude-style references during sync:

- `/spectre:foo` -> `spectre-foo`
- `@skill-spectre:spectre-foo` -> `Skill(spectre-foo)`
- `@spectre:tester` -> `@tester`
- `.claude/skills/` -> `.agents/skills/`

Do not preserve these differences manually; keep the canonical `plugins/spectre` source correct and regenerate.

## Plugin Development & Release

Claude Code caches plugins by version. There's no hot-reload — **always restart Claude after changes**.

### Local Development

```bash
claude --plugin-dir /path/to/spectre/plugins/spectre
```

Workflow:
1. Edit files
2. Restart Claude with the same command
3. Changes are active

### Testing Marketplace Distribution

```bash
# Add local marketplace
/plugin marketplace add /path/to/spectre

# Install from it
/plugin install spectre@spectre
```

### Releasing to Users

Run the LLM-led release command:

```bash
/release          # interactive — asks for patch/minor/major
/release patch    # skip the prompt
```

This handles the full flow:
1. Commits any dirty working tree changes with a descriptive message
2. Bumps version in both `plugins/spectre/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`
3. Commits the version bump as `release: vX.Y.Z`
4. Generates a changelog from commits since the last tag
5. Tags, pushes, and creates a GitHub release with the changelog

The release command is defined in `.claude/commands/release.md`.

Users update via:
```bash
/plugin marketplace update spectre
/plugin update spectre@spectre
```

## Important Notes

- Commands use `/spectre:` prefix (e.g., `/spectre:scope`)
- Project install metadata lives in `.spectre/`
- Spectre no longer installs startup hooks or managed memory injection
